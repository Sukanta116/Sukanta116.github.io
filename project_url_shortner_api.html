URL Shortener API

A secure and user-based URL shortening service built with Node.js, Express.js, MongoDB, and JWT authentication, allowing users to create and manage their own shortened URLs.

Status Completed

Overview

URL Shortener API is a secure and user-based URL shortening service that converts long URLs into short, easy-to-share links. Authenticated users can create and manage their own shortened URLs.

The project was built to understand how a realistic backend service works beyond basic CRUD operations, with a focus on REST API development, authentication, protected routes, validation, unique URL generation, HTTP redirection and frontend-backend communication.

Key features

  • User registration: users can create an account.
  • User login: users can authenticate using their credentials.
  • Password hashing: passwords are securely hashed using bcrypt.
  • JWT authentication: JWT is used to authenticate users.
  • HTTP-only cookies: authentication tokens are stored in HTTP-only cookies.
  • Protected routes: private API endpoints require authentication.
  • URL shortening: authenticated users can convert long URLs into short links.
  • Unique short identifiers: the system generates unique identifiers for shortened URLs.
  • URL history: users can view their previously created URLs.
  • URL count: the dashboard displays the number of URLs created by the user.
  • Short URL redirection: short URLs redirect users to their original URLs.
  • Request validation: incoming requests are validated on the backend.
  • User-specific URLs: each user can access their own URL history.
  • Copy shortened URLs: users can copy their generated short URLs from the dashboard.

How URL shortening works

  • An authenticated user submits a long URL.
  • The request is sent to POST /shortner.
  • The server generates a unique short identifier.
  • The URL information is saved in MongoDB.
  • The generated short URL is returned to the user.
  • When the short URL is visited, the server finds the corresponding original URL.
  • The server redirects the request to the original URL.

Authentication flow

  • A user logs in with their credentials.
  • The server validates the credentials.
  • A JWT is generated after successful authentication.
  • The JWT is stored in an HTTP-only cookie.
  • Protected requests pass through authentication middleware.
  • Authenticated user identity is used when accessing user-specific URLs.

Example endpoints

The API is organized around authentication and URL management. The following are the endpoints documented in the project.

Method Endpoint Purpose
POST /register Register a new user
POST /login Login user
POST /logout Logout the authenticated user
GET /me Get the current authenticated user
POST /shortner Create a short URL
GET /showAll Get the user's URLs
GET /:shortLink Redirect to the original URL
